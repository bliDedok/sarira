# Kelompok B — UX Reference Analysis

Kelompok B is used only to evaluate interaction patterns and information hierarchy. SARIRA must not reuse the reference brand, logo, colors, illustrations, photos, wording, icon style, or pixel composition.

## Patterns worth adopting

| Reference pattern | Why it works | SARIRA adaptation |
|---|---|---|
| One question per screen | Reduces cognitive load and makes progress predictable | Guided program creation with conditional questions |
| “Question X of Y” plus progress | Shows effort remaining | Text plus accessible progress bar; conditional total is announced accurately |
| Large answer cards | Easy scanning and tapping | SARIRA selection cards with title, short explanation, icon only when useful |
| Strong selected state | Prevents ambiguity | Checkmark, border, label, and screen-reader state; not color alone |
| One clear CTA | Reduces competing decisions | Primary “Lanjut,” “Mulai program,” or today’s program action |
| Consistent side margins | Creates rhythm | 16–20 px phone padding with full-width cards |
| Dashboard with one main indicator | Makes status understandable | Program Today completion, not calorie remaining for every user |
| Daily activities | Connects plan to action | Daily Program tasks and Weekly Action |
| Points/level | Gives lightweight feedback | Safe consistency-based points, optional and secondary |
| Stable bottom navigation | Builds orientation | Five SARIRA destinations with correct safe-area/content inset |

## Patterns to adapt rather than copy

| Reference behavior | Risk | SARIRA decision |
|---|---|---|
| Very large headlines | Can consume most of a small screen and break with large text | Use a smaller mobile H1 and content-dependent max width |
| Decorative geometry behind controls | Competes with choices and can create contrast issues | Keep decoration sparse; use warm surfaces and curated photos outside questionnaires |
| Calorie availability as universal hero | Calorie-centric framing is inappropriate for growth, healthy aging, sleep, and habit goals | Program completion is universal; nutrition is a contextual summary |
| Central plus button | Can obscure content and add a sixth destination | Do not ship initially; validate a contextual “Catat” action first |
| Card shadows everywhere | Weakens hierarchy and increases visual noise | Use surfaces/borders; reserve elevation for sheets and primary cards |
| Highly gamified header | Badges/red dots/points can compete with daily care | Place points/streak below core program information |

## Patterns rejected

- No copied colors, illustrations, mascots, logo geometry, icon assets, photos, or sentence structure.
- No literal recreation of questionnaire compositions or dashboard cards.
- No points awarded for rapid weight change, low calorie intake, or extreme exercise.
- No health-condition screen that lacks “Tidak ada,” “Tidak yakin,” and a safe follow-up path.
- No automatic assumption that a selected card should also automatically advance; explicit “Lanjut” is safer and more accessible.
- No decorative image behind critical safety, consent, or data-entry content.
- No universal calorie gauge as the product’s definition of wellness.

## SARIRA’s distinct direction

SARIRA remains recognizable through dark green, restrained lime, soft mint, warm neutral surfaces, body-neutral language, real-world lifestyle photography, and a program centered on patterns and balance. The interaction can be as simple as the reference while the product logic remains uniquely SARIRA: safety-aware eligibility, adaptive nutrition, Guided Meal/Flex Kitchen, Pattern Map, Weekly Action, and future Motion Coach.

## Testable reference-use guardrail

Before visual approval, place the SARIRA proposal and Kelompok B side by side. Reject any screen whose color distribution, illustration placement, card composition, icon treatment, or exact wording appears substantially copied. Similarity is acceptable only at the level of general mobile conventions: progress, selection cards, readable spacing, and a clear CTA.
